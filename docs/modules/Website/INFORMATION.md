# Website Module Information

## Purpose

`Modules/Website` provides the public storefront and website-facing customer/admin experience.

## Features

- Homepage and help pages.
- Product listing/detail.
- Blog listing/detail.
- Cart and coupon handling.
- Checkout and order creation.
- Login/register/logout presentation.
- Account dashboard, profile, addresses, orders and wishlist.
- Affiliate dashboard and commissions.
- Website header/footer/banner/home/flash-sale settings.
- Coupon and customer administration.
- Website API endpoint.

## Registration

The repository auto-discovers the module through `Modules/ModuleServiceProvider.php`.

`Modules/Website/Config/module.php` declares:

- type: `domain`
- enabled: `true`
- dependencies: `User`, `Product`, `Category`, `Post`, `Order`
- manifest permissions: `view_website`, `create_website`, `edit_website`, `delete_website`

## Routes

Main route files:

- `Modules/Website/routes/web.php`
- `Modules/Website/routes/api.php`

Public route groups include home, help, product, blog, cart, checkout and account.

Admin routes use `/admin` with `web` and `auth:admin` middleware.

Known route limitation: `checkout.momo.callback` currently targets `CheckoutController@momoCallback`, but the method is absent from the controller.

## Permissions

The module manifest declares generic Website CRUD-style permissions, but the inspected admin route group does not apply capability-specific permission middleware. Individual Livewire mutation authorization is incomplete.

Multiple old migration files are named with malformed `-0001_11_30_*` timestamps.

## Relationships

Important conceptual relationships include:

- Cart -> CartItems -> Products.
- Cart -> Coupon.
- Order -> OrderItems / OrderHistory.
- Product -> categories/reviews/flash-sale items.
- User -> addresses/orders/wishlist/affiliate data.
- HeaderMenu -> HeaderMenuItems.
- FooterColumn -> FooterLinks.

Exact relationship ownership should be normalized against Product, Category, Post, Order and User modules during refactor.

## Events / Jobs

No canonical Website-specific event/job architecture was established from the inspected tree. Long-running or external workflows should be verified before implementation changes.

## Configuration / Environment Variables

Module configuration lives under `Modules/Website/Config`.

A module `.env.example` is present. Nested Website services also contain environment/configuration management code, which should not be treated as canonical Website domain ownership.

## Known Limitations

- Missing `CheckoutController@momoCallback` for an active route.
- Broad admin authorization boundary.
- Missing permission checks in some admin Livewire mutations.
- Checkout stock concurrency is not protected by row locking.
- Checkout saves a cart after deleting it.
- Duplicate/cross-domain models and services.
- Unbounded-style admin list/select behavior.
- Malformed historical migration names.
- Limited automated test evidence.

## Maintenance Notes

Use `ANALYSIS.md` as the decision document before refactoring. Preserve public routes and behavior while migrating domain ownership in small steps. Do not remove duplicate models/services until all active callers are identified and migrated.
